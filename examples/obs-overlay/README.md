# 嗷呜点歌机 OBS 只读展示示例

这是一个无需构建工具的静态网页示例，只读取嗷呜点歌机的本机接口，不包含按钮、控制逻辑或 `POST` 请求。它会展示当前歌曲、点歌人、待播队列、暂停点歌/暂停代播状态，以及接口和播放器连接状态。

## 在 OBS 中直接使用

1. 在嗷呜点歌机“基础设置”中开启外部只读 HTTP API 和 WebSocket。
2. 在 OBS 中添加“浏览器”来源。
3. 填写点歌机内置的本机地址：

   ```text
   http://127.0.0.1:5556/overlay/
   ```

4. 建议浏览器源尺寸设为 `1920 × 1080`。画布完全透明，只有左上角的组件会被绘制；可在 OBS 中裁剪或变换来源来摆放组件。

正常运行时，组件只保留顶部的接口连接提示。暂停自动代播时左侧播放区域会变为红色，暂停接收点歌时右侧待播队列会变为红色；播放器断开时才显示底部异常提示。

如果修改了接口端口，只需修改网址中的端口；页面会自动使用自身端口：

```text
http://127.0.0.1:6000/overlay/?maxQueue=8
```

当前点歌机发布包会把本目录作为内置 UI 一起打包。`/overlay/` 是固定宿主页，安装或切换 Mod UI 后地址不变，OBS 会自动载入当前启用的版本；不需要用户另行启动网页服务器。

## URL 参数

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| `port` | 当前页面端口 | 可选覆盖外部只读 API 端口，范围 `1-65535`；本地文件调试时默认 `5556`。 |
| `maxQueue` | `3` | 展示的待播歌曲数，范围 `1-30`；标题仍显示完整队列数量。 |

例如只显示前三首：

```text
http://127.0.0.1:5556/overlay/?maxQueue=3
```

## 作为二次开发参考

- `index.html`：无交互的展示结构。
- `styles.css`：透明画布上的单组件布局；宽屏为横向播放与队列，窄屏自动改为纵向。
- `app.js`：WebSocket 优先、HTTP 轮询兜底和自动重连。
- `overlay.json`：Mod UI 包清单。ZIP 必须把它与入口 HTML 放在根目录。

页面优先连接：

```text
ws://127.0.0.1:5556/ws
```

收到 `{ "type": "state", "data": ... }` 后刷新页面。WebSocket 不可用时，会每 3 秒读取一次：

```text
GET http://127.0.0.1:5556/api/v1/state
```

新版开关字段为：

- `service.requestIntake`：是否接收新点歌；
- `service.queuePlayback`：是否自动代播点歌队列，它不等于音乐播放器本身的真实播放/暂停状态。

示例兼容旧版顶层 `accepting` 和 `playing` 字段。所有歌名、歌手和点歌人等外部文本都通过 `textContent` 写入 DOM；自行扩展时请继续避免把这些内容拼进 `innerHTML`。

完整协议见 [`../../docs/external-api.md`](../../docs/external-api.md)，Mod 打包规范见 [`../../docs/overlay-mods.md`](../../docs/overlay-mods.md)。接口只绑定 `127.0.0.1`，不要把它直接转发到局域网或公网。
